# AIrtg schema - agent memory

AIrtg schema: the wire contract (Apache-2.0, see `LICENSE`) between AIrtg producers (collectors
such as snmp-poller, GPLv3) and consumers (the analyzer, proprietary). This file is the
project's agent memory: keep it current. User-facing docs, including every contract rule, live
in `README.md`.

## Hard requirements (do not regress)

- **Public and permissive**: Apache-2.0 so that GPL collectors and the proprietary analyzer can
  both import it. Never copy code from GPL repos here. No dependency beyond
  `google.golang.org/protobuf` in the main module.
- **Messages**: `proto/airtg/v1/*.proto`, package `airtg.v1`. Every message, field, enum and
  value is documented (`buf lint` COMMENTS): the comments are the reference. Every message on
  the wire is one `Envelope` (id, schema_version, producer = type/version/hostname/id, time,
  tenant_id, oneof payload: `metrics` = `MetricBatch`, `inventory` = `Inventory`). New
  payloads (events, logs, topology) are new oneof fields (numbers 12+).
- **Compatibility**: nothing incompatible within `airtg.v1` (`buf breaking` WIRE_JSON: no
  removal, renumbering, retyping or renaming). Incompatible = new package `airtg/v2` next to
  v1; the Go module stays v1. `make breaking` compares with the last `v*` tag: fails from
  1.0.0, warns before.
- **Generated code**: `airtg/` is generated by `make generate` (buf, `clean: true`: wiped
  every run) and committed; never put hand-written code there. `make check` fails when it is
  stale. protoc-gen-go is a tool of the main `go.mod` (same version as the runtime); buf is
  a tool of `tools/go.mod` (own module so its dependencies never reach consumers).
- **Transport** (`schema.go`): JetStream subjects `airtg.v1.metrics.<token>` and
  `airtg.v1.inventory.<token>`, `<token>` = `Token(device id)` (keeps `[A-Za-z0-9_-]`, other
  bytes `~xx` lowercase hex, injective, `ParseToken` reverses). `Nats-Msg-Id` = Envelope.id.
  Ids (device id; tenant id and producer id when set): `^[A-Za-z0-9][A-Za-z0-9._-]*$`,
  <= 255 bytes (`ValidID`), same rule as snmp-poller ids. `Device.id` is the id from the
  producer's point of view (snmp-poller: the configured one), not the only identity forever:
  cluster ids or discovered ids (serial, ...) may be added later as new `Device` fields.
  `tenant_id` and `Producer.id` are empty on premises, for SaaS later.
- **`Envelope.tenant_id` is for debugging and logging ONLY** (user decision). Never use it,
  in the schema docs, in producers or in consumers, for authorization, isolation or routing:
  a producer can claim any tenant. The real tenant is the one of the producer's
  authentication (its NATS account); ids are unique within that authenticated tenant. Do not
  weaken this wording or suggest other uses of the field.
- **Version**: `VERSION` (MAJOR.MINOR.PATCH, Go tags need all three), embedded as
  `schema.Version`. CI (`.github/workflows/go.yml`) checks every push/PR; a push to main
  whose version has no tag `v<version>` creates the tag and a GitHub release. Never create
  release tags by hand.
- **Fixtures** (`fixtures/`): defined in `fixtures_test.go`, files in `fixtures/v1/`
  (`<name>.binpb` + `<name>.json`, `unknown-payload` binary only), exposed as `fixtures.FS`.
  Append-only: `make fixtures` (`-update`) only writes missing files; tests compare files
  with definitions semantically (`proto.Equal`; protojson output is unstable on purpose) and
  reject files without a definition. `TestContract` checks fixtures follow the README rules.
- **Dependabot**: gomod (`/` and `/tools`, one group) and github-actions, weekly. A protobuf
  bump needs `make generate` on its branch (generated header changes).

## Testing notes

- `make` runs every check; `make breaking` needs tags. To test the failure paths of
  `generated-check` and `breaking`, copy the repo to a scratch dir, commit, tag, then change
  a proto or a fixture there: never tag this repo by hand.
- `fixtures/v1/` must never be empty (`go:embed` fails to compile): to rewrite every
  fixture before the first release, add a temporary empty file there, `make fixtures`, then
  remove it.
- `.gen-check/` is `make generated-check`'s output (git-ignored, emptied by buf itself).

## Layout

- `proto/airtg/v1/` - the messages (`envelope`, `device`, `metrics`, `inventory`).
- `airtg/v1/` - generated Go code (package `airtgv1`).
- `schema.go` - version and NATS binding (package `schema`).
- `fixtures/` - golden messages and their tests.
- `buf.yaml`, `buf.gen.yaml` - lint, breaking and generation settings.
- `tools/` - module pinning buf.
